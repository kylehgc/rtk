# Merge-based tracking fork of rtk-ai/rtk

Upstream rtk-ai/rtk is active but slow: 100+ open community PRs with good fixes going unreviewed. This fork (kylehgc/rtk) stays based on upstream `develop` and periodically pulls it in with `git merge upstream/develop` — never rebasing published history — while cherry-picking curated community PRs and original fixes as regular commits on top. Adoptions and original fixes are done on topic branches and merged into `develop` through fork PRs; only clean upstream syncs commit to `develop` directly — a sync with merge conflicts also goes through a fork PR, so any removal of fork work (e.g. upstream superseding a fork fix) is recorded and reviewable (see CONTEXT.md, "Conflicted Sync").

Merge-based (not a rebase overlay) because the fork accepts external contributions: rebasing would rewrite history and break every branch based on it. Not a divergent fork because upstream still merges fixes we want for free; divergence remains an escape hatch if upstream dies.
